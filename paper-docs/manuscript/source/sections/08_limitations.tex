\section{Limitations}
\label{sec:limitations}

Complete-model timing and numerical agreement are based on a single execution of the $103$-token
benchmark. This supports the reported execution cost and correctness comparison but not run-to-run
variance, encrypted task accuracy, or input-domain numerical generality. The input was selected
deterministically as the first positive genomic-signal record, not randomly or by prediction margin.

The protocol requires the key holder to remain available at the predetermined nonlinear and refresh
boundaries. Availability and throughput therefore differ from non-interactive HE systems.

Client and server are roles inside one program on one node. Boundary calls perform the
cryptographic operations directly, without ciphertext serialization, network transport, or a key
custody service. A physical client boundary crossing is therefore not a network message. A derived
schedule accounts for ciphertext objects and minimum dependency phases, but serialized byte volume,
bandwidth sensitivity, transport latency, and production key handling remain unknown.

Encryption begins at embedded numeric vectors. Tokenization, token-index lookup in the embedding
table, and construction of the initial embedding occur before the encrypted boundary. The evaluated
deployment assumes that the tokenizer and embedding table are distributed to the client. Private
lookup is required if a provider will not make those components available.

Model confidentiality is not a cryptographic goal of the protocol. The data owner observes
intermediate activations at the client boundaries, which may expose information useful for model
extraction. We do not evaluate such attacks; server-side model placement is an operational
deployment choice rather than model protection.

CKKS decryption is approximate. The client never returns a decoded value to the server, only a
freshly encrypted result, but the server selects the ciphertext supplied to each declared
boundary. Security analyses of approximate homomorphic encryption show why adversarially selected
decryption queries require care~\cite{limicciancio2021}. The semi-honest threat model rules out
deviations from the declared schedule, and the current re-encryption path applies no noise
flooding. Numerical headroom alone does not establish a secure flooding parameter. Selecting and
validating that budget remains future work.
