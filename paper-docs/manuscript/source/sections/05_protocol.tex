\subsection{Nonlinearity boundaries}
CKKS carries the affine maps, reductions, residual additions, and attention products without
exposing an activation to the compute provider. The difficulty lies in three nonlinearity classes:
the inverse square root in LayerNorm, causal softmax, and GELU. We place a declared client boundary
at each class. For LayerNorm, the server computes the encrypted mean and variance and sends only the
variance term needed for the inverse square root. For attention, it sends encrypted causal score
tiles and receives encrypted softmax weights. The GELU boundary operates on the packed MLP
activations.

At every boundary, the data owner decrypts values derived from its own query, evaluates the declared
function exactly in double precision, and encrypts the result afresh. The data owner already holds
the secret key and is the only party that decrypts. The compute provider receives neither a
plaintext activation nor the secret key. Between these declared calls, the ciphertext lineage
remains on the server and every model operation is evaluated homomorphically.
Figure~\ref{fig:architecture} shows the resulting evaluation order for one transformer block and
which party performs each step.

\subsection{Non-interactive design}
The non-interactive design keeps a single ciphertext lineage and replaces every
nonlinearity with a polynomial approximation. It completed one released-weight transformer block,
establishing that the block arithmetic can be expressed without intermediate decryption. The
stopping point appeared when the same design was configured for multi-block composition: context
and evaluation-key loading exceeded the tested 80~GB GPU memory envelope before useful composition
arithmetic began.

The mechanism matters more than the failure location. Repeated polynomial approximation lengthens
the multiplicative path, which requires a deeper modulus budget and a bootstrapping schedule, and
the associated context and evaluation-key material must be resident before evaluation; composition
therefore failed as a memory problem rather than as a numerical-correctness problem. Since published
non-interactive systems evaluate encoders of comparable depth and width on a single accelerator at
these parameters (Section~\ref{sec:related}), this reports where our non-interactive configuration
stopped, not where the approach stops. It does identify the measured pressure that the
client-assisted design removes: exact client evaluation shortens each encrypted segment and replaces
encrypted bootstrapping with fresh encryption at already declared boundaries.

\begin{algorithm*}[!tb]
\caption{Evaluating one transformer block. $G=13$ token groups; $\odot$ is homomorphic
multiplication; every operation outside a \textsc{Client} call runs on ciphertexts.}
\label{alg:block}
\begin{algorithmic}[1]
\Require encrypted activations $c_0,\dots,c_{G-1}$; public weights $W$
\Statex \textit{Stage 1: normalization and projection}
\For{$g \gets 0$ \textbf{to} $G-1$}
  \State $n \gets \Call{LayerNorm}{c_g,\ \gamma_1}$ \Comment{Algorithm~\ref{alg:layernorm}}
  \State $\beta \gets \Call{BabyRotations}{n}$ \Comment{$N_1-1$ rotations, shared}
  \State $Q_g,K_g,V_g \gets \Call{MatMul}{\beta,W_q},\ \Call{MatMul}{\beta,W_k},\
         \Call{MatMul}{\beta,W_v}$
\EndFor
\State \Call{FlushEncodedWeights}{} \Comment{bounds host memory to one stage}
\Statex \textit{Stage 2: causal attention scores}
\For{$k \gets 0$ \textbf{to} $G-1$}
  \State $\tilde{K} \gets \{\Call{LaneShift}{K_k,\delta}\}$ for each $\delta$ required by a
         later query group
  \For{$q \gets k$ \textbf{to} $G-1$}
    \State $S \gets 0$
    \For{$\delta \in \Call{ActiveShifts}{q,k}$}
      \State $P \gets Q_q \odot \tilde{K}_\delta$
      \For{$h \gets 0$ \textbf{to} $H-1$}
        \State $S \gets S + \Call{ReduceSum}{P \odot \mathrm{mask}_h} \odot
               \mathrm{isolate}(q,k,\delta,h)/\sqrt{d_h}$
      \EndFor
    \EndFor
    \State \Call{Client.TakeScoreTile}{$S,q,k$} \Comment{decrypt only}
  \EndFor
\EndFor
\State \Call{Client.Softmax}{} \Comment{stable softmax over complete causal rows}
\Statex \textit{Stage 3: attention context}
\For{$k \gets 0$ \textbf{to} $G-1$}
  \State $\tilde{V} \gets \{\Call{LaneShift}{V_k,\delta}\}$
  \For{$q \gets k$ \textbf{to} $G-1$; $\ \delta \in \Call{ActiveShifts}{q,k}$}
    \State $A \gets \Call{Client.EmitWeightTile}{q,k,\delta}$ \Comment{re-encrypt only}
    \State $C_q \gets C_q + A \odot \tilde{V}_\delta$
  \EndFor
\EndFor
\Statex \textit{Stages 4 and 5: projection, MLP, residuals}
\For{$g \gets 0$ \textbf{to} $G-1$}
  \State $R_g \gets c_g + \Call{MatMul}{\Call{BabyRotations}{C_g},W_{\text{proj}}}$
\EndFor
\State \Call{FlushEncodedWeights}{}
\For{$g \gets 0$ \textbf{to} $G-1$}
  \State $\beta \gets \Call{BabyRotations}{\Call{LayerNorm}{R_g,\gamma_2}}$
  \State $h \gets \sum_{c<4} \Call{MatMul}{\beta,W_{\text{fc}}^{c}} \odot \mathrm{copy}_c$
  \State $a \gets \Call{Client.GELU}{h}$
  \State $c'_g \gets R_g + \sum_{c<4}
         \Call{MatMul}{\Call{BabyRotations}{a \odot \mathrm{copy}_c},W_{\text{mlp}}^{c}}$
\EndFor
\State \Return $c'_0,\dots,c'_{G-1}$
\end{algorithmic}
\end{algorithm*}

\begin{algorithm}[t]
\caption{The client boundary. The data owner is the only party holding $\mathsf{sk}$, and every
value it decrypts derives from its own query.}
\label{alg:boundary}
\begin{algorithmic}[1]
\Function{ClientBoundary}{$c$, $f$}
  \State $v \gets \Call{Decode}{\Call{Decrypt}{\mathsf{sk},c}}$
  \State $v' \gets f(v)$ \Comment{evaluated exactly, in double precision}
  \State \Return $\Call{Encrypt}{\mathsf{pk},\Call{Encode}{v'}}$ \Comment{fresh ciphertext at
         level $0$}
\EndFunction
\end{algorithmic}
\end{algorithm}

Fresh encryption in Algorithm~\ref{alg:boundary} returns the activation to level~$0$, so every
client boundary fully resets the multiplicative budget. The configured depth of $13$ therefore
bounds the longest encrypted run between consecutive boundaries. It does not accumulate across the
$12$ transformer blocks.

\begin{algorithm}[t]
\caption{LayerNorm. The server computes both statistics under encryption; only the inverse square
root crosses the boundary. The released checkpoint carries no bias term.}
\label{alg:layernorm}
\begin{algorithmic}[1]
\Function{LayerNorm}{$x$, $\gamma$}
  \State $\mu \gets \Call{ReduceSum}{x}\odot(1/D)$
  \State $z \gets x - \mu$
  \State $\sigma^2 \gets \Call{ReduceSum}{z \odot z}\odot(1/D) + \varepsilon$
  \State $r \gets \Call{ClientBoundary}{\sigma^2,\ t \mapsto t^{-1/2}}$
  \State \Return $(z \odot r) \odot \gamma$
\EndFunction
\end{algorithmic}
\end{algorithm}

\begin{algorithm}[t]
\caption{Packed matrix product, baby-step giant-step over the packed diagonals.
$N_1 = N_2 = 32$ and $N_1N_2 = W = 1024$.}
\label{alg:matmul}
\begin{algorithmic}[1]
\Function{MatMul}{$\beta$, $M$}
  \State $d \gets \Call{EncodedDiagonals}{M,\ \mathrm{level}(\beta_0)}$
         \Comment{encoded once, cloned per use}
  \State $y \gets 0$
  \For{$j \gets 0$ \textbf{to} $N_2-1$}
    \State $u \gets \sum_{i<N_1} \beta_i \odot \Call{Clone}{d_{N_1 j + i}}$
    \State $y \gets y + (j = 0\ ?\ u : \Call{Rot}{u, B N_1 j})$
  \EndFor
  \State \Return $y$
\EndFunction
\end{algorithmic}
\end{algorithm}

The algorithms also expose the protocol transcript. Its order and size are determined by the
circuit and sequence length, never by decrypted content. The evaluated block makes $857$ physical
client boundary crossings, including $91$ score-tile decryptions and $727$ weight-tile encryptions
for attention. Attention therefore accounts for $818$ of the $857$ client calls, or $95.4\%$.
In directional object accounting it contributes $818$ of the block's $896$ boundary ciphertext
objects, or $91.3\%$. These homogeneous counts identify attention as the main boundary-schedule
target without treating the implementation's mixed-unit logical-instance counter as scalar work.
The implementation validates the complete operation schedule, boundary counts, and remaining depth
on every run and aborts when any differs. Section~\ref{sec:optimization} can thus treat an
unchanged circuit as a checked invariant rather than as an assurance.

\subsection{Packing}
Each ciphertext has $32{,}768$ usable slots, indexed by activation copy, padded feature, and token
lane. The layout assigns these slots as $4$ copies by $1{,}024$ features by $8$ token lanes, with
the token lane as the innermost index. Rotations by whole-lane strides can therefore move features
without mixing tokens, while smaller rotations align tokens within a group. The released hidden
width of $768$ occupies part of the padded feature region; the remainder supplies the
power-of-two width required by the linear transform and staging space for per-head attention
scores. In dense transforms, rows and columns outside the active width contribute zeros; padding
therefore affects cost without changing the numerical result.

The four copies match the MLP expansion from width $768$ to $3{,}072$. They let its expansion
chunks occupy parallel regions of one ciphertext rather than requiring a separate wide layout.
The $103$ tokens fill $13$ ciphertext groups, with padding in the final group. Within a
dense transform, a $32\times32$ baby-step giant-step decomposition covers the $1{,}024$ padded
features; baby rotations are shared where the schedule permits. Packing eight tokens together
reduces the number of dense encrypted products from $1{,}236$ serial-equivalent products to $156$,
a structural reduction of $7.92\times$. No latency factor follows from that operation count alone.

\subsection{Causal attention}
Attention follows a chunked lower-triangular schedule over the $13$ token groups. Only causal group
pairs are visited, producing $91$ encrypted score tiles. Shifts needed by several later query
groups are materialized per key group and reused. The client collects all score tiles before
applying stable softmax over complete causal rows; normalization is therefore a global
synchronization point in this design. It then emits the encrypted weight tiles consumed by the
context computation.

Plaintext model weights do not eliminate ciphertext--ciphertext multiplication inside attention:
both query--key scoring and softmax-weight--value aggregation multiply one activation-derived
quantity by another. Of the block's $1{,}506$ ciphertext--ciphertext multiplications, LayerNorm
contributes $26$ centered-value squares and $26$ products with client-returned inverse square
roots. Attention contributes $727$ query--key products and $727$ weight--value products, accounting
for $97\%$ of the total. The latter term follows directly from returning exact attention weights
as fresh ciphertexts; it is the arithmetic price paid to keep the attention nonlinearity exact at
the client boundary.

\subsection{Depth and parameters}
The retained CKKS context uses ring dimension $65{,}536$, yielding $32{,}768$ usable slots at a
$128$-bit classical security level. It uses $50$-bit scaling, a $60$-bit first modulus, $3$
hybrid key-switching digits, and $80$ rotation keys. Multiplicative depth $13$ is the smallest
demonstrated passing depth for this scale, digit count, ring, and packing. The block completes with
$6$ of the $13$ levels remaining. The retained setting is the demonstrated feasible point in this
parameter space; parameter optimization is a separate experiment.

\subsection{Composition across blocks}
Composition uses a declared full-hidden-state client refresh between blocks. The data owner decrypts
the packed block output, restores its token-vector layout, and encrypts fresh level-$0$ inputs for
the next block under the same context and key lineage. The complete evaluation uses that mechanism
throughout, with $11$ full-hidden-state refreshes and one last-token refresh into the task head;
Section~\ref{sec:results} reports the measured outcome.
