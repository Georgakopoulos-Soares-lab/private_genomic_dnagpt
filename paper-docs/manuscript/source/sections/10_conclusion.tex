\section{Conclusion}

We show that client-assisted CKKS can execute all twelve DNAGPT transformer blocks and the task head
from encrypted embedded inputs at the $103$-token benchmark, the longest prompt among the
encrypted-scope classification tasks. The predeclared relative-error tolerance was
$4\times10^{-2}$; the observed classification-margin error was $8.56\times10^{-9}$, and the
prediction matched the plaintext reference. Client refresh keeps the maximum multiplicative depth
at $13$ and avoids homomorphic bootstrapping, with GPU memory remaining bounded across blocks.

The principal limitation is runtime: the complete benchmark requires $1.86$~hours on one A100. This
is unsuitable for conventional interactive inference, but it may represent an acceptable trade-off
in low-volume settings where a provider retains a model server-side and a data owner prioritizes
genomic confidentiality against a semi-honest provider. Improving provider-side encrypted
throughput and evaluating a real networked deployment are the main steps toward practical use.

\subsection*{Future work}

Future work should repeat complete-model evaluation across a predeclared set of genomic inputs and
obtain repeated latency measurements. The main systems target is provider-side encrypted throughput,
including additional plaintext caching and improved packed linear transforms. A deployable
implementation must add serialized network transport and private embedding lookup. Stronger
deployment security also requires a validated re-encryption and noise-flooding strategy.

\section*{Ethics statement}

This study involved no human participants, specimens, or private clinical records. It used public
reference datasets with recorded provenance. The work makes no clinical-performance claim and
does not present the prototype as a deployable privacy guarantee beyond its stated threat model.

\section*{Data availability statement}

All evaluation datasets are public. Their original sources, versions, preprocessing, and any
recovery route used are recorded in the repository's data-provenance document. Sequence data,
model weights, and cryptographic keys are not redistributed.

The evaluation harnesses, encrypted-evaluation implementation, environment definitions, and the

license. Upstream model code, released weights, and evaluation datasets retain the licenses of
their original distributors and are not redistributed here.
