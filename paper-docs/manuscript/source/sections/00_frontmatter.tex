\section*{Abstract}

\textbf{Motivation.} Genomic sequence is identifying and cannot be replaced after disclosure. We
ask whether a provider can execute a released genomic transformer without receiving the genomic
input in plaintext, and where numerical agreement, memory, or cost limits that deployment.

\textbf{Results.} We validate DNAGPT on three genomic task families and construct an independently
checked numerical reference. In the client-assisted design, the provider evaluates every linear
operation on ciphertexts under one key lineage; the key holder evaluates LayerNorm inverse square
roots, causal softmax, and GELU exactly, at boundaries fixed before execution. All $12$ released
blocks and the task head execute from encrypted embedded vectors with declared client refreshes and
no homomorphic bootstrap, leaving the released weights and nonlinear formulas unmodified. For the
one prompt evaluated, the decrypted label matches the reference and its margin has
$8.56\times10^{-9}$ relative error, $6.67$ orders of magnitude below the $4\times10^{-2}$ tolerance
fixed in advance; no polynomial approximation of a nonlinearity contributes to that residual.
Client refresh holds multiplicative depth at $13$, and device-wide GPU memory used reaches
$9839$~MiB without growing by block index. One in-process execution takes $1.86$~hours on an A100
GPU node. A pure non-interactive configuration completes one released-weight block, then exceeds
the tested $80$~GB accelerator-memory envelope on its composition context and evaluation keys,
placing that barrier in the nonlinear schedule rather than in the model's dense maps.

\textbf{Conclusions.} The executed case establishes complete-model graph feasibility and numerical
agreement for one input, and locates the limiting barrier in throughput rather than in correctness
or accelerator memory. Client refresh bounds multiplicative depth by the longest encrypted segment
rather than by network depth, which is what makes the twelve-block lineage expressible without
bootstrapping; stage-bounded plaintext caching separately prevents host-side accumulation. The
current single-process implementation is not practical for interactive use and has not been
evaluated as a networked service, so feasibility and practicality are reported as separate
verdicts.

\textbf{Availability.} Code, evaluation harnesses, and the evidence record are maintained at
\url{https://github.com/Georgakopoulos-Soares-lab/private_genomic_dnagpt}.

% --- Key points -------------------------------------------------------------
\section*{Key Points}

\begin{itemize}
  \item All twelve released DNAGPT blocks and the task head execute from encrypted embedded vectors
        at the $103$-token task prompt, under one key lineage and without any homomorphic
        bootstrap. The released weights and nonlinear formulas are preserved unmodified, and the one
        evaluated prompt reproduces the reference label with $8.56\times10^{-9}$ relative margin
        error.
  \item The validation chain separately records released float32 behavior, checks an independent
        NumPy float64 reference against a float64-cast PyTorch shadow, and compares encrypted
        execution with that reference.
  \item Because client refresh bounds depth by the longest encrypted segment rather than by network
        depth, multiplicative depth stays at $13$ and device-wide GPU memory used stays at
        $9839$~MiB across the complete model, with no growth by block index. Stage-bounded caching
        separately limits host memory while preserving the asserted operation schedule.
  \item One in-process execution takes $1.86$~hours and requires an online key holder, so the
        evaluated form is not interactive. Feasibility and practicality are therefore reported as
        separate verdicts: complete-model feasibility is established for the evaluated prompt, while
        encrypted task accuracy, service rate, and networked deployment remain open.
\end{itemize}
