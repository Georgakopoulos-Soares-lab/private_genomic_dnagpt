% --- Abstract ---------------------------------------------------------------
\section*{Abstract}

\textbf{Motivation.} Genomic sequence identifies its contributor and cannot be replaced once it
has been disclosed. When a genomic model is available only as a service, using it ordinarily means
handing that sequence to the provider. We ask whether a provider can instead evaluate a genomic
transformer without receiving the genomic input in plaintext, and where numerical agreement,
memory, or cost would stop such a deployment.

\textbf{Results.} We first reproduce DNAGPT on three genomic task families and record its plaintext
predictions as the numerical reference for encrypted evaluation. A fully non-interactive CKKS
implementation must approximate the transformer nonlinearities homomorphically. In our evaluated
configuration, one transformer block completes, but multi-block composition exceeds the tested
$80$~GB accelerator-memory envelope. We therefore use a client-assisted protocol: the provider
evaluates the transformer on encrypted input representations, while the data owner evaluates the
LayerNorm inverse square root, causal softmax, and GELU at predetermined boundaries. The client
decrypts only its own intermediate values and returns fresh encryptions. These refreshes reset the
multiplicative-depth budget and remove the need for homomorphic bootstrapping in the evaluated
protocol. All $12$ transformer blocks and the task head execute from encrypted embedded vectors
without modifying the model. At the $103$-token benchmark---the longest prompt among the
encrypted-scope classification tasks---the decrypted prediction matches the plaintext reference.
We fixed a relative-error tolerance of $4\times10^{-2}$ before encrypted evaluation. The observed
classification-margin error is $8.56\times10^{-9}$, $6.67$ orders of magnitude below that threshold;
the exact client-side nonlinear functions contribute no polynomial-approximation error. The maximum
multiplicative depth between consecutive refreshes remains $13$. Device-wide GPU memory used peaks
at $9839$~MiB and does not increase across transformer blocks. The complete benchmark takes
$1.86$~hours on one A100 GPU node.

\textbf{Conclusions.} Client-assisted CKKS makes complete DNAGPT transformer inference from
encrypted embeddings feasible within the tested accelerator-memory envelope. Client-side
evaluation of the nonlinearities bounds multiplicative depth and avoids homomorphic bootstrapping,
while stage-scoped plaintext caching controls host memory. The $1.86$-hour runtime of the
$103$-token benchmark is unsuitable for conventional interactive inference, making provider-side
encrypted throughput the principal remaining systems limitation.

\textbf{Availability.} Code, evaluation harnesses, and the evidence record are maintained at
\url{https://github.com/Georgakopoulos-Soares-lab/private_genomic_dnagpt}.

% --- Key points -------------------------------------------------------------
\section*{Key Points}

\begin{itemize}
  \item \textbf{The complete model runs on encrypted input.} All twelve transformer blocks and the
        task head execute at the $103$-token benchmark, the longest prompt among the encrypted-scope
        classification tasks. The numerical tolerance was fixed at $4\times10^{-2}$ before encrypted
        evaluation; the observed classification-margin error is $8.56\times10^{-9}$, $6.67$ orders
        of magnitude lower.
  \item \textbf{Encrypted outputs are validated against an independent plaintext reference.} We
        implement the transformer computation independently in PyTorch float64 and NumPy float64
        and compare them after every transformer block and the task head. After agreement is
        established, the NumPy implementation supplies the reference for encrypted execution.
  \item \textbf{Client refresh bounds multiplicative depth and avoids bootstrapping.} Fresh
        encryption after each client-evaluated nonlinearity resets the level budget. The maximum
        multiplicative depth therefore remains $13$ throughout the twelve-block model, while
        device-wide GPU memory used peaks at $9839$~MiB without block-over-block growth.
  \item \textbf{The current trade-off favors privacy over latency.} The $103$-token benchmark takes
        $1.86$~hours on one A100 and is unsuitable for conventional interactive querying. It may
        still serve low-volume settings in which a provider retains the model server-side and the
        data owner accepts higher latency to keep genomic information confidential from a
        semi-honest provider. Production throughput and networked deployment remain unmeasured.
\end{itemize}
